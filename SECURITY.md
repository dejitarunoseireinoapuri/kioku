# Seguridad de Kioku

No comunicar vulnerabilidades con claves, recuerdos, audios o datos privados mediante una issue pública. Usar un canal privado acordado con el propietario; el contacto público de seguridad está pendiente.

Si una credencial se filtra, revocarla o rotarla y revisar su uso. Borrar un archivo del último commit no elimina el secreto del historial. No pegar credenciales ni registros sensibles en chats, issues o informes.

La política técnica está en [docs/05-security/SECURITY.md](docs/05-security/SECURITY.md); el [modelo de amenazas](docs/05-security/THREAT_MODEL.md) describe las fronteras de confianza y las comprobaciones necesarias.

No existe todavía una versión distribuida ni una auditoría de seguridad superada. Esta documentación define requisitos, no certifica que estén implementados.
